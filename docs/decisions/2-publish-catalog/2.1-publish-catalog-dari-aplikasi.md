# 2.1 Publish Catalog dari Aplikasi

[← Kembali ke 2. Publish Catalog](./README.md)

> **TL;DR:** setiap kali aplikasi di-build, daftar error lengkapnya dikirim ke tempat yang dipilih di config, misalnya folder storage, server lain lewat SFTP, atau endpoint HTTP, tanpa membuat deployment bergantung pada tujuan tersebut.

## Tujuan

Menetapkan cara aplikasi mengirim catalog ke luar aplikasi: identitas aplikasi, isi kiriman, tujuan yang didukung, dan perilaku ketika publish gagal.

## Keputusan

### Batas Package

Package hanya menyediakan sisi pengirim. Package tidak menyediakan aplikasi penerima, penyimpanan riwayat, pencarian, atau dashboard. Apa yang dilakukan dengan catalog setelah sampai di tujuan menjadi urusan sistem penerima.

### Command

Publish dilakukan melalui Artisan command:

```shell
php artisan error-definition:publish --revision=<commit-sha>
```

Command menyusun catalog di memory melalui shared pipeline [Decision 1.10](../1-error-definition-framework/1.10-generator-error-codes-typescript.md), termasuk discovery dan pemeriksaan EDF linter, lalu mengirimkannya melalui driver yang dipilih. Command tidak membaca file `catalog_path`.

Option `--revision` wajib diisi dengan identitas source revision yang sedang di-build, umumnya commit SHA dari CI.

### Identitas Aplikasi

Setiap aplikasi memiliki identitas tetap pada config `publish.application`. Nilainya berupa slug huruf kecil:

```regex
^[a-z0-9]+(?:-[a-z0-9]+)*$
```

Contoh: `surat-masuk`, `kepegawaian`.

Identitas aplikasi tidak diambil dari `APP_NAME`. Command gagal sebelum mengirim apa pun jika `publish.application` kosong atau tidak sesuai format.

### Isi Kiriman

Kiriman membungkus catalog [Decision 1.11](../1-error-definition-framework/1.11-generator-error-catalog-json.md) tanpa mengubah isinya:

```json
{
  "application": "surat-masuk",
  "revision": "a1b2c3d4e5f6",
  "catalog": {
    "schemaVersion": 1,
    "errors": [
      {
        "code": "SM-WF-001",
        "message": "Draft sedang dikunci.",
        "category": "workflow",
        "httpStatus": 409,
        "severity": "medium",
        "retryable": false
      }
    ]
  }
}
```

Setiap publish mengirim catalog lengkap aplikasi, bukan hanya perubahan. Error code yang tidak lagi ada pada catalog berarti sudah dihapus dari aplikasi pada revision tersebut.

Isi kiriman sama untuk semua driver dan mengikuti JSON Schema [Decision 2.2](./2.2-validasi-schema.md).

### Driver

Tujuan publish dipilih melalui `publish.driver`. Package menyediakan dua driver.

#### `disk`

Menulis kiriman sebagai file JSON ke [filesystem disk Laravel](https://laravel.com/docs/filesystem) yang disebut pada `publish.disk.name`, dengan path `publish.disk.path`. Placeholder `{application}` pada path diganti dengan identitas aplikasi.

```php
'disk' => [
    'name' => env('EDF_PUBLISH_DISK', 'local'),
    'path' => 'error-definition/{application}.json',
],
```

File ditimpa pada setiap publish sehingga selalu berisi catalog terakhir. Disk dapat berupa `local`, `s3`, `sftp`, atau disk lain yang didukung Laravel. Kebutuhan menyalin ke server lain dipenuhi dengan disk `sftp` atau langkah CI terpisah, misalnya `rsync`, terhadap file hasil disk `local`. Package tidak menjalankan `rsync` atau perintah shell lain.

#### `http`

Mengirim `POST` ke `publish.http.url` dengan `Content-Type: application/json`. URL dipakai apa adanya tanpa path tambahan.

Jika `publish.http.token` diisi, command mengirim header `Authorization: Bearer <token>`. URL dan token dibaca dari environment variable melalui config, tidak ditulis langsung pada file config yang di-commit.

| Status | Exit code command |
|--------|-------------------|
| `2xx` | `0` |
| Lainnya, timeout, atau network error | `1` |

Pada respons selain `2xx`, command menampilkan status HTTP dan field `message` dari body jika ada. Command menunggu respons paling lama `publish.http.timeout` detik dan tidak melakukan retry otomatis.

### Posisi pada CI

Publish dijalankan sebagai langkah CI yang terpisah dari deployment. Kegagalan publish membuat langkah tersebut gagal, tetapi tidak menghentikan atau membatalkan deployment.

## Alasan

Driver yang dapat dipilih membuat package tidak memaksakan satu jenis penerima. Tim yang hanya butuh file di server bersama tidak perlu membangun endpoint, sedangkan tim yang sudah memiliki service penerima dapat memakai HTTP.

Driver `disk` memakai filesystem Laravel agar lokasi lokal, object storage, dan server lain melalui SFTP ditangani dengan config yang sudah dikenal developer Laravel, tanpa package menjalankan perintah shell.

Menyusun catalog di memory memastikan yang dikirim selalu sesuai dengan source yang sedang di-build. Membaca file `catalog_path` berisiko mengirim artifact lama dari build sebelumnya.

Identitas aplikasi dipisahkan dari `APP_NAME` karena `APP_NAME` adalah nama tampilan yang dapat berubah. Penerima memerlukan key yang stabil untuk membedakan catalog antar-aplikasi.

Revision diwajibkan agar penerima dapat mencocokkan catalog dengan kode yang menghasilkannya.

Catalog lengkap dipilih dibanding kiriman perubahan karena kiriman yang gagal tidak membuat data penerima menyimpang dari aplikasi. Kiriman berikutnya selalu memperbaiki keadaan.

Envelope dipisahkan dari catalog agar `schemaVersion` dan isi catalog tetap identik dengan artifact Decision 1.11, sedangkan identitas aplikasi dan revision menjadi urusan publish.

Retry otomatis tidak disediakan karena CI sudah memiliki mekanisme menjalankan ulang langkah yang gagal.

Deployment tidak bergantung pada publish sesuai [Decision 1.1.1](../1-error-definition-framework/1.1.1-batas-metadata-runtime-dan-registry.md): sistem penerima adalah consumer, bukan dependency aplikasi.

✅ **Contoh:** Tim menyimpan catalog semua aplikasi di satu server dokumentasi internal → setiap aplikasi memakai driver `disk` dengan disk `sftp` yang mengarah ke server tersebut, sehingga tidak perlu ada service penerima.

❌ **Bukan contoh:** Menambahkan driver yang menjalankan `rsync` dari dalam command → package bergantung pada binary dan SSH key di mesin CI, padahal disk `sftp` atau langkah CI terpisah sudah memenuhi kebutuhan yang sama.

## Keputusan Terkait

- Penerima sebagai consumer ditetapkan pada [Decision 1.1.1](../1-error-definition-framework/1.1.1-batas-metadata-runtime-dan-registry.md).
- Shared generation pipeline ditetapkan pada [Decision 1.10](../1-error-definition-framework/1.10-generator-error-codes-typescript.md).
- Bentuk catalog ditetapkan pada [Decision 1.11](../1-error-definition-framework/1.11-generator-error-catalog-json.md).
- JSON Schema kiriman ditetapkan pada [Decision 2.2](./2.2-validasi-schema.md).
- Config key tercatat pada [Configuration Reference](../../reference/configuration.md).

## Konsekuensi

- Setiap aplikasi wajib memiliki `publish.application` yang stabil sebelum dapat publish.
- CI harus menyediakan commit SHA dan, untuk driver `http` atau disk remote, menyimpan credential sebagai secret.
- Disk `s3` dan `sftp` memerlukan Flysystem adapter yang dipasang oleh aplikasi, bukan oleh package.
- Driver `disk` hanya menyimpan catalog terakhir per aplikasi; riwayat menjadi urusan penerima.
- Penghapusan error code terdeteksi dari catalog lengkap, tanpa perintah hapus terpisah.
- Data di tujuan dapat tertinggal dari aplikasi selama publish gagal dan belum dijalankan ulang.
- Package tidak menyediakan aplikasi penerima.
